## 2. 배경

### 2.1 AI 서비스 환경의 변화

최근 AI 서비스는 클라우드 기반의 대규모 모델을 넘어, **On-Device 환경**에서도 빠르고 안정적으로 동작하는 경량 모델에 대한 요구가 급격히 증가하고 있습니다.

### 2.2 경량화의 필요성

특히 다음과 같은 제약으로 인해 모델 크기를 줄이면서도 성능을 유지하는 기술이 중요한 과제로 부상하고 있습니다:

- **응답 지연 (Latency)**: 실시간 서비스를 위한 빠른 응답 필요
- **메모리 사용량**: 제한된 디바이스 메모리 환경
- **운영 비용**: 클라우드 인프라 비용 절감

### 2.3 EXAONE 모델 현황

EXAONE은 다음과 같은 모델 라인업을 보유하고 있습니다:

| 모델 유형 | 설명 |
|----------|------|
| **Large-scale 모델** | Global Frontier 급 대규모 모델 |
| **Small-scale 모델** | 노트북·모바일 등 제한된 환경에서 활용 가능한 모델 |

### 2.4 단순 파라미터 축소의 한계

단순히 파라미터 수를 줄이는 방식은:
- **장점**: 메모리와 속도 측면에서 유리
- **단점**: **정확도 저하**라는 명확한 한계를 동반

### 2.5 해커톤의 목표

이번 해커톤은 이러한 문제의식을 바탕으로, **EXAONE 모델을 대상으로 한 실전 중심의 LLM 경량화**를 수행하게 됩니다.

목표:
- 모델 크기를 효과적으로 축소
- 성능 저하를 최소화
- 실제 추론 환경에서의 효율을 극대화

## 3. 주제 및 설명

### 3.1 주제

**LLM 경량화 (Large Language Model Compression)**

### 3.2 기본 모델

| 항목 | 내용 |
|------|------|
| **모델명** | EXAONE-4.0-1.2B |
| **파라미터 수** | 1.2B (12억 개) |
| **용도** | 경량화 대상 기본 모델 |

### 3.3 수행 내용

참가자는 다음 과정을 수행합니다:

1. **모델 구조와 특성 분석**
   - EXAONE-4.0-1.2B 모델의 아키텍처 이해
   - 경량화 가능 영역 파악

2. **경량화 기법 적용**
   - 다양한 경량화 기법 적용
   - 필요 시 추가 학습·튜닝

3. **최적화 목표**
   - 모델 크기
   - 추론 속도
   - 성능 간의 균형 최적화

### 3.4 평가 환경

- 경량화된 모델은 **vLLM 기반 추론 엔진 환경**에서 평가
- 동일한 추론 파이프라인 조건 하에서 모델 성능과 효율을 비교
- 단순한 파라미터 감소에 국한되지 않고, **실제 서비스 환경에서의 추론 효율과 성능**을 함께 고려

## 5. 평가 기준

### 5.1 평가 공식

최종 점수는 다음 공식으로 계산됩니다:

```
Score = max(0.5 × PerfNorm_model + 0.5 × SpeedNorm_model, 0)
```

### 5.2 성능 정규화 (PerfNorm)

모델의 성능을 베이스 모델 대비 정규화한 값입니다.

```
PerfNorm_model = Perf_model / Perf_base_model
```

| 변수 | 설명 |
|------|------|
| `Perf_model` | 경량화된 모델의 성능 |
| `Perf_base_model` | 기본 모델(EXAONE-4.0-1.2B)의 성능 |

### 5.3 속도 정규화 (SpeedNorm)

모델의 추론 속도를 베이스 모델 대비 정규화한 값입니다.

```
SpeedNorm_model = 1 - (Time_model / Tokens_model) / (Time_base_model / Tokens_base_model)
```

| 변수 | 설명 |
|------|------|
| `Time_model` | 경량화된 모델의 추론 시간 |
| `Tokens_model` | 경량화된 모델의 생성 토큰 수 |
| `Time_base_model` | 기본 모델의 추론 시간 |
| `Tokens_base_model` | 기본 모델의 생성 토큰 수 |

### 5.4 평가 가중치

| 항목 | 가중치 |
|------|--------|
| 성능 (PerfNorm) | **50%** |
| 속도 (SpeedNorm) | **50%** |

### 5.5 점수 해석

- **Score > 0**: 유효한 제출
- **Score = 0**: 최소 점수 (음수는 0으로 처리)
- **PerfNorm = 1.0**: 베이스 모델과 동일한 성능
- **SpeedNorm > 0**: 베이스 모델보다 빠른 추론 속도

## 6. 코드 제출 가이드

### 6.1 제출 형식

| 항목 | 내용 |
|------|------|
| **제출 방식** | submit.zip 업로드 |
| **포함 내용** | 허깅페이스(Hugging Face) 표준 형식의 모델 가중치 및 설정 파일 |

### 6.2 제출 제한

| 제한 항목 | 값 |
|----------|-----|
| **전체 추론 실행 시간** | ≤ **20분** |
| **제출 파일 용량** | ≤ **10GB** |
| **압축 해제 후 용량** | ≤ **32GB** |

### 6.3 실행 환경

| 리소스 | 사양 |
|--------|------|
| **CPU** | 6 vCPU |
| **RAM** | 28GB |
| **GPU** | L4 GPU |
| **VRAM** | 22.4GiB |

### 6.4 평가 방식

- 제출된 모델은 **참가자 코드가 아닌**, 운영진이 제공하는 **고정된 추론 스크립트**에서 실행되어 평가됩니다.
- 모든 모델은 **동일한 vLLM 추론 환경**에서 실행됩니다.

### 6.5 허깅페이스 표준 형식

submit.zip에 포함되어야 하는 파일들:

```
submit/
├── config.json              # 모델 설정 파일
├── model.safetensors        # 모델 가중치 (또는 pytorch_model.bin)
├── tokenizer.json           # 토크나이저 설정
├── tokenizer_config.json    # 토크나이저 추가 설정
├── special_tokens_map.json  # 특수 토큰 매핑
└── (기타 필요한 파일들)
```
