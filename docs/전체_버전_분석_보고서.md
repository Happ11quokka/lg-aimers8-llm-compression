## 3. 평가 체계

### 3.1 점수 공식

```
Score = max(0.5 × PerfNorm + 0.5 × SpeedNorm, 0)
```

#### PerfNorm (성능 유지율)

```
PerfNorm = Perf_model / Perf_baseline
```

- 원본 모델 대비 벤치마크 성능 비율
- 1에 가까울수록 원본과 유사한 성능
- 평가 벤치마크: GSM8K, AIME 등 (lm-evaluation-harness 사용)

#### SpeedNorm (속도 향상률)

```
SpeedNorm = 1 - (Time_model / Tokens_model) / (Time_baseline / Tokens_baseline)
```

- 토큰당 추론 시간의 상대적 개선율
- 양수일수록 베이스라인보다 빠름
- 예: 0.3이면 베이스라인 대비 30% 빠름

### 3.2 점수 향상 전략의 트레이드오프

```
              PerfNorm ↑          SpeedNorm ↑
              (성능 유지)          (속도 향상)
                 │                    │
    ┌────────────┤                    ├────────────┐
    │            │                    │            │
  더 정밀한    더 많은           더 공격적인    더 효율적인
  양자화      캘리브레이션       압축          추론 커널
  (group=64)  (512+ 샘플)      (3-bit 등)    (Marlin)
    │            │                    │            │
    └─── 크기↑ ──┘                    └─── 성능↓ ──┘
```

## 4. 경량화 기법 이론

### 4.1 GPTQ (Post-Training Quantization)

#### 4.1.1 이론적 배경

GPTQ는 2022년 Frantar et al.이 제안한 Post-Training Quantization(PTQ) 기법으로, **Optimal Brain Surgeon (OBS)** 프레임워크를 기반으로 합니다.

**핵심 아이디어**: 가중치를 양자화할 때 발생하는 오차를 아직 양자화하지 않은 가중치에 보상(compensation)하여 전체 양자화 오차를 최소화합니다.

#### 4.1.2 수학적 원리

양자화 목표는 다음 최적화 문제를 푸는 것입니다:

```
min_Ŵ  ||WX - ŴX||²
```

여기서:
- `W`: 원래 가중치 행렬
- `Ŵ`: 양자화된 가중치 행렬
- `X`: 캘리브레이션 데이터의 활성화 값

GPTQ는 이를 행(row) 단위로 분해하여 순차적으로 해결합니다:

1. **Hessian 행렬 계산**: `H = 2X·Xᵀ` (입력 활성화의 외적)
2. **순차적 양자화**: 각 가중치 `w_q`를 양자화하고
3. **오차 보상**: 나머지 가중치를 업데이트하여 오차를 보상

```
δ_F = (w_q - quant(w_q)) / [H⁻¹]_qq
w_j ← w_j - δ_F · [H⁻¹]_qj / [H⁻¹]_qq  (j > q인 모든 가중치)
```

#### 4.1.3 주요 파라미터

| 파라미터 | 설명 | 기본값 | 효과 |
|----------|------|--------|------|
| `scheme` | 양자화 스킴 | W4A16 | 가중치 4bit, 활성화 16bit |
| `block_size` (group_size) | 그룹 양자화 크기 | 128 | 작을수록 정밀, 크기 증가 |
| `dampening_frac` | Hessian 대각 댐핑 비율 | 0.01 | Hessian 역행렬의 수치 안정성 |
| `actorder` | 양자화 순서 결정 방법 | None | "weight": 가중치 크기 순, "static": 고정 |
| `targets` | 양자화 대상 레이어 타입 | ["Linear"] | 선형 레이어만 적용 |
| `ignore` | 양자화 제외 레이어 | [] | embed_tokens, lm_head 등 |

#### 4.1.4 W4A16 양자화 상세

```
W4A16: 4-bit Weight, 16-bit Activation

가중치 저장 방식:
┌─────────────────────────────────────┐
│  원본 가중치 (FP16): 16 bits/param  │
│  ↓                                  │
│  양자화된 가중치: 4 bits/param       │
│  + scale factor: FP16 per group     │
│  + zero point: INT4 per group       │
└─────────────────────────────────────┘

그룹 양자화 (group_size=128):
[w1, w2, ..., w128] → scale₁, zero₁, [q1, q2, ..., q128]
[w129, w130, ..., w256] → scale₂, zero₂, [q129, ..., q256]
...

복원: ŵᵢ = scaleᵢ × (qᵢ - zeroᵢ)
```

#### 4.1.5 actorder 옵션 상세

```
actorder=None (기본):
  → 가중치를 원래 순서대로 양자화
  → 가장 빠른 양자화, 보통 성능

actorder="static":
  → 열(column) 인덱스 순서대로 양자화
  → 베이스라인에서 사용된 설정

actorder="weight":
  → 가중치의 절대값 크기 순서로 양자화
  → 큰 가중치를 먼저 양자화하여 오차 보상 효과 극대화
  → 정확도 ~2% 향상 (llmcompressor v0.8.0+)
  → Marlin 커널과 호환
```

#### 4.1.6 dampening_frac 상세

```
Hessian 행렬의 수치 안정성을 위한 댐핑:
  H' = H + λ · diag(H)

여기서 λ = dampening_frac

- 0.01 (높음): 안전하지만 양자화 정밀도 약간 감소
- 0.001 (낮음): 더 정밀한 양자화, 수치적으로 덜 안정
- 0.0008 (미세조정): 최적점 탐색용
```

### 4.1.7 본 프로젝트에서의 GPTQ 적용

```python
from llmcompressor.modifiers.quantization import GPTQModifier

recipe = [
    GPTQModifier(
        scheme="W4A16",              # 4-bit 가중치, 16-bit 활성화
        targets=["Linear"],          # 모든 Linear 레이어 대상
        ignore=["embed_tokens", "lm_head"],  # 임베딩 제외
        block_size=128,              # 그룹 크기 (Marlin 호환)
        dampening_frac=0.001,        # Hessian 댐핑
        actorder="weight",           # 가중치 기반 순서
    )
]

oneshot(
    model=model,
    dataset=calibration_ds,
    recipe=recipe,
    max_seq_length=512,
    num_calibration_samples=256,
)
```

### 4.2 AWQ (Activation-Aware Weight Quantization)

#### 4.2.1 이론적 배경

AWQ는 2023년 Lin et al.이 제안한 기법으로, **활성화 분포를 분석하여 중요한 가중치를 보호**하는 방식입니다. GPTQ가 Hessian 기반 오차 보상이라면, AWQ는 채널별 스케일링을 통해 중요한 가중치의 양자화 오차를 줄입니다.

#### 4.2.2 핵심 관찰

```
모든 가중치가 동일하게 중요하지 않다!

가중치 W의 각 채널의 중요도 ∝ 해당 채널의 활성화 크기

활성화 값이 큰 채널의 가중치:
  → 작은 양자화 오차도 출력에 큰 영향
  → 이 채널을 보호해야 함

활성화 값이 작은 채널의 가중치:
  → 양자화 오차가 출력에 미치는 영향 작음
  → 공격적 양자화 가능
```

#### 4.2.3 수학적 원리

1. **채널별 중요도 계산**:
   ```
   s_j = mean(|X_j|)  (j번째 입력 채널의 평균 활성화 크기)
   ```

2. **스케일 팩터 계산**:
   ```
   α_j = s_j^β  (β는 하이퍼파라미터, 보통 0.5~1.0)
   ```

3. **스케일링 후 양자화**:
   ```
   W' = W · diag(α)         (가중치 스케일 업)
   X' = X · diag(1/α)       (활성화 스케일 다운)

   W'X' = W · diag(α) · diag(1/α) · X = WX  (수학적으로 동일)

   하지만 양자화 시:
   quant(W') ≈ W'  (중요 채널이 스케일업되어 양자화 오차 감소)
   ```

#### 4.2.4 AWQ vs GPTQ 비교

| 특성 | GPTQ | AWQ |
|------|------|-----|
| 핵심 원리 | Hessian 기반 오차 보상 | 활성화 기반 스케일링 |
| 양자화 속도 | 느림 (Hessian 역행렬) | 빠름 (스케일링만) |
| 과적합 위험 | 있음 (캘리브레이션 데이터 의존) | 낮음 |
| vLLM 추론 속도 | 712 tok/s (Marlin) | **741 tok/s** (Marlin) |
| TTFT | 118ms | 137ms |
| ITL | 13.8ms | **12.6ms** |
| 정확도 | 높음 | 높음 (유사) |

#### 4.2.5 본 프로젝트에서의 AWQ 적용

llmcompressor에서는 GPTQModifier의 `actorder="static"` 설정으로 AWQ와 유사한 효과를 냅니다:

```python

    GPTQModifier(

        block_size=128,
        dampening_frac=0.01,     # AWQ 스타일은 0.01 권장
        actorder="static",       # AWQ 유사 효과
    )
]
```

### 4.3 SparseGPT (Structured Sparsity)

#### 4.3.1 이론적 배경

SparseGPT는 2023년 Frantar & Alistarh가 제안한 기법으로, **대규모 언어 모델에 대해 재학습 없이 비정형/정형 가지치기(pruning)**를 수행합니다. GPTQ와 같은 OBS 프레임워크를 기반으로 하되, 가중치를 0으로 설정하는 것이 목표입니다.

#### 4.3.2 Pruning의 종류

```
1. 비정형 가지치기 (Unstructured Pruning):
   ┌─────────────────┐     ┌─────────────────┐
   │ 1.2  0.5  0.8   │     │ 1.2  0    0.8   │
   │ 0.3  0.9  0.1   │ →   │ 0    0.9  0     │
   │ 0.7  0.2  0.6   │     │ 0.7  0    0.6   │
   └─────────────────┘     └─────────────────┘
   - 개별 가중치 단위로 제거
   - 높은 희소율 가능하지만 GPU 가속 어려움

2. 정형 가지치기 2:4 (Structured 2:4 Sparsity):
   ┌─────────────────────┐     ┌─────────────────────┐
   │ 1.2  0.5  0.8  0.3  │     │ 1.2  0    0.8  0    │
   │ 0.3  0.9  0.1  0.7  │ →   │ 0    0.9  0    0.7  │
   │ 0.7  0.2  0.6  0.4  │     │ 0.7  0    0.6  0    │
   └─────────────────────┘     └─────────────────────┘
   - 4개 가중치 중 2개를 0으로 설정 (50% 희소율)
   - NVIDIA Ampere+ GPU에서 하드웨어 가속 지원
   - 2배 속도 향상 가능
```

#### 4.3.3 SparseGPT 알고리즘

```
입력: 가중치 행렬 W, 활성화 X, 목표 희소율 s
출력: 희소 가중치 행렬 Ŵ

1. Hessian 계산: H = X·Xᵀ
2. 각 행(row)에 대해:
   a. 마스크 M 결정 (크기가 작은 가중치를 0으로)
   b. 제거된 가중치의 오차를 나머지에 보상:
      δ_j = Σ (w_pruned · H⁻¹_pruned,j / H⁻¹_j,j)
   c. 보상된 가중치 업데이트
3. 결과: 50% 가중치가 0이면서 성능 유지
```

#### 4.3.4 Sparsity + Quantization 조합

```
단계 1: SparseGPT로 50% 가지치기
  원본 가중치 [1.2, 0.5, 0.8, 0.3]
  → 희소 가중치 [1.2, 0, 0.8, 0] (2:4 구조)

단계 2: GPTQ로 4-bit 양자화
  희소 가중치 [1.2, 0, 0.8, 0]
  → 양자화 [Q(1.2), 0, Q(0.8), 0]

이론적 압축률:
  FP16 (16bit) → 50% Sparse + W4 = 실질 2bit/param
  압축 배수: 8x (FP16 대비)
```

#### 4.3.5 본 프로젝트에서의 적용

```python
from llmcompressor.modifiers.pruning import SparseGPTModifier

recipe = [
    # Step 1: SparseGPT 희소화
    SparseGPTModifier(
        sparsity=0.5,           # 50% 가중치 제거
        targets=["Linear"],
        sequential_update=True,  # 순차적 업데이트 (정확도 향상)
    ),

    # Step 2: GPTQ 양자화
    GPTQModifier(
        scheme="W4A16",
        targets=["Linear"],
        ignore=["embed_tokens", "lm_head"],
        block_size=128,
    )
]
```

#### 4.3.6 실험 결과 및 한계

- 모델 크기: 1.42 GB (비희소 W4와 동일) - 희소 텐서가 compressed_tensors 포맷으로 저장되나, 4-bit 양자화 후 크기 이점이 제한적
- vLLM의 2:4 sparse 커널 지원 여부가 불확실하여 속도 이점 미확인
- 성능 하락 위험: 50% 가중치 제거 + 4bit 양자화의 이중 손실

### 4.4 Mixed-Precision Quantization

#### 4.4.1 이론적 배경

Mixed-Precision(혼합 정밀도) 양자화는 **모든 레이어에 동일한 비트폭을 적용하는 대신, 레이어의 민감도에 따라 다른 비트폭을 할당**하는 전략입니다.

#### 4.4.2 레이어 민감도 분석

```
트랜스포머 모델의 일반적 민감도 패턴:

민감도
  ↑
  │
5 │ ██                                              ██
  │ ██ ██                                        ██ ██
4 │ ██ ██                                        ██ ██
  │ ██ ██ ██                                  ██ ██ ██
3 │ ██ ██ ██                                  ██ ██ ██
  │ ██ ██ ██                                  ██ ██ ██
2 │ ██ ██ ██ ██ ██ ██ ██ ██ ██ ██ ██ ██ ██ ██ ██ ██ ██
  │ ██ ██ ██ ██ ██ ██ ██ ██ ██ ██ ██ ██ ██ ██ ██ ██ ██
1 │ ██ ██ ██ ██ ██ ██ ██ ██ ██ ██ ██ ██ ██ ██ ██ ██ ██
  └─────────────────────────────────────────────────────→
    L0 L1 L2 L3  ...        중간 레이어         ... L28 L29

  초기 레이어 (★★★★★): 입력 표현 형성에 핵심
  중간 레이어 (★★☆☆☆): 양자화에 robust
  후기 레이어 (★★★★★): 출력 품질 결정에 핵심
```

#### 4.4.3 전략

```
Mixed-Precision 전략 (EXAONE-4.0-1.2B):

레이어 0-1   → FP16 유지 (양자화 제외)    ← 입력 처리 핵심
레이어 2-27  → W4A16 양자화               ← 안전한 영역
레이어 28-29 → FP16 유지 (양자화 제외)    ← 출력 품질 핵심

장점: 민감한 레이어의 정보 손실 방지 → PerfNorm 향상
단점: FP16 레이어가 늘어나면 모델 크기 증가 → SpeedNorm 하락
```

#### 4.4.4 본 프로젝트에서의 적용

```python
SENSITIVE_LAYERS = [
    "model.layers.0",
    "model.layers.1",
    "model.layers.28",
    "model.layers.29",
]

ALWAYS_IGNORE = ["embed_tokens", "lm_head"]

# 민감 레이어를 ignore 목록에 추가하여 FP16 유지
ignore_layers = ALWAYS_IGNORE + SENSITIVE_LAYERS

recipe = [
    GPTQModifier(
        scheme="W4A16",
        targets=["Linear"],
        ignore=ignore_layers,    # 민감 레이어 + 임베딩 제외
        block_size=128,
    )
]
```

#### 4.4.5 트레이드오프 분석

```
민감 레이어 4개 FP16 유지 시:
  - 추가 FP16 메모리: 4 × 35.66M × 2 bytes ≈ 285 MB
  - W4 절약분 대비 차이: 4 × 35.66M × 1.5 bytes ≈ 214 MB 추가

  PerfNorm: ↑ (민감 레이어 보호)
  SpeedNorm: ↓ (모델 크기 증가 → 추론 시 메모리 대역폭 증가)
```

### 4.5 Marlin 커널 최적화

#### 4.5.1 이론적 배경

Marlin은 **NVIDIA GPU용 고속 4-bit 양자화 추론 커널**입니다. 일반적인 dequantize-then-multiply 방식이 아닌, **양자화된 가중치를 직접 사용하는 최적화된 CUDA 커널**을 제공합니다.

#### 4.5.2 작동 원리

```
일반 GPTQ 추론:
  INT4 가중치 → dequantize → FP16 가중치 → GEMM → 출력
  (메모리 대역폭 병목 + dequantize 오버헤드)

Marlin 커널 추론:
  INT4 가중치 → 최적화된 INT4-FP16 혼합 GEMM → 출력
  (dequantize 없이 직접 연산, 메모리 효율적)

속도 향상:
  - 일반 GPTQ: ~276 tok/s
  - Marlin-GPTQ: ~712 tok/s (2.6배)
  - Marlin-AWQ: ~741 tok/s (2.7배)
```

#### 4.5.3 Marlin 호환 조건

```
Marlin 커널 자동 적용 조건 (vLLM):
├─ 양자화 스킴: W4A16 (4-bit weight only)
├─ group_size: 128 (필수!)
├─ symmetric: true (대칭 양자화)
├─ GPU: Ampere 이상 (Ada Lovelace L4 지원)
└─ 포맷: GPTQ 또는 AWQ compressed_tensors

vLLM이 모델 로드 시 자동으로 감지하여 Marlin 적용
별도 설정 불필요!
```

#### 4.5.4 Marlin이 중요한 이유

```
해커톤 점수 = 0.5 × PerfNorm + 0.5 × SpeedNorm
                                    ↑
                               Marlin이 영향

SpeedNorm = 1 - (Time_model/Tokens_model) / (Time_base/Tokens_base)

Marlin 적용 시:
  Time_model 감소 → SpeedNorm 증가 → 전체 점수 향상

  모델 크기(압축률)가 같아도 추론 커널이 빠르면 SpeedNorm 향상!
```

## 7. 실험에서 얻은 교훈

### 7.1 vLLM 호환성은 최우선

```
❌ lm_head 양자화 → tie_word_embeddings 깨짐 → vLLM 로드 실패
✅ embed_tokens + lm_head는 반드시 ignore 유지

핵심 규칙:
  IGNORE = ["embed_tokens", "lm_head"]  # 절대 변경 금지!
```

### 7.2 캘리브레이션 강화의 역설

```
예상: 더 많은 캘리브레이션 = 더 좋은 양자화 = 더 높은 점수
현실:
  - 256샘플/512길이 → 0.5955점 (최고)
  - 384샘플/768길이 → 점수 하락
  - 512샘플/1024길이 → 점수 하락

원인 분석:
  1. 캘리브레이션 과적합: 더 많은 데이터에 특화된 양자화
  2. 양자화 시간 증가: 같은 하드웨어에서 더 오래 걸림
  3. Hessian 추정 변화: 더 많은 샘플이 항상 더 나은 Hessian을 의미하지 않음

교훈: "적당한" 캘리브레이션이 최적일 수 있다
```

### 7.3 Marlin 호환이 SpeedNorm의 핵심

```
group_size=128이 Marlin 커널의 필수 조건

group_size=64로 PerfNorm을 높여도:
  → Marlin 비호환 → 추론 속도 2~3배 느림 → SpeedNorm 급락
  → 총점 오히려 하락

결론: group_size=128 고정이 최적
```

### 7.4 actorder="weight"의 효과 확인

```
베이스라인의 actorder 설정이 이미 "weight"였음
→ 이후 static(AWQ 스타일)과 비교했을 때 weight가 더 나은 성능

actorder="weight"가 최적인 이유:
  - 큰 가중치를 먼저 양자화 → 오차 보상 극대화
  - 중요한 가중치의 양자화 정밀도 우선 보장
```

### 7.5 dampening_frac의 미세한 영향

```
0.01   → 안전하지만 양자화 정밀도 약간 손실
0.001  → 최적 (최고 점수 달성)
0.0008 → 미세 조정 시도 (이론적으로 더 정밀)

dampening은 Hessian 역행렬의 수치 안정성 vs 양자화 정밀도의 트레이드오프
너무 작으면 수치적으로 불안정, 너무 크면 양자화 부정확
```

### 7.6 Sparsity는 현 환경에서 효과 제한적

```
SparseGPT + GPTQ 조합:
  - 이론적으로 2:4 sparsity + W4 = 실질 2bit 압축
  - 현실: vLLM의 sparse 커널 자동 적용 미확인
  - 4-bit 양자화 후 sparse 메타데이터 오버헤드
  - 크기 이점 없이 성능만 하락할 위험

Phase 3 (vLLM 수정 가능)에서 재시도 가치 있음
```

### 7.7 최적 설정 요약

```
현재까지 발견된 최적 조합:

GPTQModifier(
    scheme="W4A16",
    targets=["Linear"],
    ignore=["embed_tokens", "lm_head"],
    block_size=128,         # Marlin 호환 필수
    dampening_frac=0.001,   # 최적값
    actorder="weight",      # 정확도 향상
)

캘리브레이션:
    num_samples=256         # 과적합 방지
    max_seq_length=512      # 적당한 컨텍스트

→ 최고 점수: 0.5955 (9분 58초 추론)
```
